## Що таке «піветинг» (pivoting)?

**Піветинг** — це перехід від одного факту до іншого через встановлений зв'язок. Це ключова навичка OSINT-аналітика.

**Приклад:**
```
Домен example[.]com
  → WHOIS email: admin@protonmail.com
    → Той самий email в профілі GitHub
      → GitHub profile: username "johnadams"
        → Ім'я у GitHub commits: "John Adams"
          → LinkedIn: John Adams, CEO @ Example Inc
```

Кожен стрілка — це **півот**. Obsidian граф робить ці переходи **видимими і клікабельними**.

## Два методи роботи

Автор репозиторію описує два підходи і **не вважає один кращим за інший** — кожен підходить для різних ситуацій:

### Метод 1: Вглиб (Follow the branch)

```
Починаєте з домену → проходите ВСІ його гілки до кінця перед тим,
як перейти до наступної сутності.
```

**Переваги:**
- Більш вичерпний результат
- Чіткіші зв'язки в графі
- Менше шансів пропустити важливий пів'от

**Недоліки:**
- Набагато більше часу
- Ризик потрапити в "чорну діру" нерелевантних деталей

**Коли використовувати:** Коли маєте час, ціль — одна конкретна сутність, важлива повнота.

---

### Метод 2: Вшир (Record pivot points as you go)

```
Рухаєтесь за логікою і джерелами → записуєте всі точки піветингу →
повертаєтесь до порожніх листів пізніше.
```

**Переваги:**
- Швидко будується загальна картина
- Інтуїтивно, слідує природному ходу думки
- Краще, коли джерела самі підказують напрямок

**Недоліки:**
- Ризик тунельного зору (слідуєте тільки тим шляхом, де знайшли щось цікаве)
- Можна пропустити піводи, якщо занадто покладатись на інструменти

**Коли використовувати:** Розвідка на ранній стадії, кілька паралельних цілей, обмежений час.

> **Практична рекомендація:** Починайте з Методу 2 для загальної картини, потім застосовуйте Метод 1 до найбільш перспективних гілок.

## Як читати граф розслідування

### Вузли (nodes)

Кожен вузол = одна нотатка. Розмір вузла залежить від кількості посилань на нього:

```
Великий вузол → на нього посилаються багато інших нотаток
               → це HUB — ключова сутність розслідування
```

### Ребра (edges) і стрілки

Стрілка показує **напрямок посилання**:
```
Person → Account    (Людина МАЄ акаунт)
Domain → IP         (Домен хоститься на IP)
Account → Domain    (Акаунт пов'язаний з доменом)
```

Увімкніть **Arrows** в Graph Display — це покаже напрямок зв'язків.

### Orphans (сироти)

Вузли без жодного зв'язку — це нотатки, де ще не встановлено контекст. Увімкніть orphans у фільтрах — це ваш **список пріоритетів для продовження роботи**.

## Практичний приклад: домен → людина

**Початкові дані:** Підозрілий домен `fasttrade-global[.]com`

```
Крок 1: Новий файл → шаблон Domain
  → Заповнюєте WHOIS: email admin@fasttrade-global.com
  → Заповнюєте Analytics: UA-12345678

Крок 2: Google Analytics ID UA-12345678
  → Той самий ID на 3 інших доменах:
    [[fasttrade-eu.com]], [[trademaster-hub.com]], [[globalfin-corp.io]]
  → Ці домени вже посилаються на fasttrade-global → графові зв'язки готові

Крок 3: WHOIS admin@fasttrade-global.com
  → Historicals: реєструвався також як "vadym.koval@gmail.com"
  → Новий файл → шаблон Person → Vadym Koval
  → [[Vadym_Koval]] посилається на всі 4 домени

Крок 4: LinkedIn пошук "Vadym Koval"
  → Знайдено: Vadym Koval, Director @ FastTrade Global LLC
  → Нова нотатка → шаблон Organization → [[FastTrade_Global_LLC]]
  → FastTrade_Global_LLC → Director: [[Vadym_Koval]]
```

**Граф на цьому етапі:**
```
Vadym_Koval ────────── fasttrade-global[.]com
     │                       │
     │               fasttrade-eu.com
     │               trademaster-hub.com
     │               globalfin-corp.io
     │
FastTrade_Global_LLC
```

Один Analytics ID привів від домену → до людини → до компанії → до мережі з 4 доменів.

## Bulk Rename для масового імпорту

Якщо інструмент повертає список субдоменів або акаунтів:

```
sub1.fasttrade-global.com
sub2.fasttrade-global.com
mail.fasttrade-global.com
```

1. Скопіюйте список у Obsidian
2. Плагін **Bulk Rename** → regex `^(.*)$` → replace `[[$1]]`
3. Отримуєте `[[sub1.fasttrade-global.com]]`, `[[sub2...]]` тощо
4. Вставляєте в нотатку домену → Obsidian автоматично будує зв'язки

## Graph Analysis: фінальний прохід

Після завершення розслідування:

```
Community Plugins → Graph Analysis → вибрати алгоритм
```

**Coreness** — знаходить найбільш зв'язані вузли (ваші HUBs).  
**Similarity** — знаходить вузли зі схожими зв'язками (можливо, одна і та сама особа під різними іменами).  
**Link Prediction** — пропонує зв'язки, яких ще немає в графі, але статистично вони мали б бути.

Використовуйте **Adjacency Matrix Maker** як альтернативу, коли граф занадто щільний для візуального аналізу.
