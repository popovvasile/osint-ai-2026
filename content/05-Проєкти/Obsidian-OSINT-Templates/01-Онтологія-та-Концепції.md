# Obsidian OSINT Templates — Онтологія та Концепції

> **Проєкт:** [[05-Проєкти/Obsidian-OSINT-Templates/index|Obsidian OSINT Templates]]

## Що таке «актант» і «власність»?

Кожна сутність у цій системі належить до однієї з двох категорій:

**Актант (Actant)** — той, хто діє або може діяти. Має власну волю або місію.
- `Person` — фізична особа
- `Organization` — компанія, установа, група

**Власність (Possession)** — те, чим актант **володіє або що контролює**. Не діє самостійно.
- Акаунт, домен, IP, телефон, актив, криптогаманець, інтелектуальна власність

**Контекст (Context)** — обставини, в яких відбуваються дії.
- `Event` — подія з прив'язкою до місця і часу

> **Чому це важливо?** Якщо аналітик плутає актанта і власність — граф деградує. Наприклад: акаунт у соцмережі — це власність, а не актант. Поки власник невідомий, акаунт — власність без батька. Коли атрибуція встановлена — з'являється зв'язок до `Person` або `Organization`.

## Батьківські і дочірні вузли

Кожна сутність може бути:
- **Parent** — мати дочірні вузли (посилатись на інших)
- **Child** — бути дочірньою (на неї посилаються)
- **Both** — і те, і інше

| Сутність | Parent / Child / Both | Логіка |
|----------|-----------------------|--------|
| Person | Both | Людина має акаунти (Child), але може управляти організацією (Parent) |
| Organization | Both | Має домени і людей, але сама входить в холдинг |
| Account | Child | Акаунт завжди належить комусь |
| Asset | Child | Актив завжди чийсь |
| Domain | Both | Домен має IP і субдомени, але сам є власністю |
| Event | Parent | Подія породжує індикатори і TTPs |
| TTP | Both | TTP пов'язані між собою і містять Weapon Systems |
| Indicator | Both | Індикатор вказує на TTP і одночасно є результатом Event |

## Властивості сутностей

Кожна нотатка-сутність має чотири стандартних властивості у frontmatter:

```yaml
---
aliases:        # Інші назви (псевдоніми, maiden name, скорочення)
tags:           # Унікальний тег сутності — ОДИН на тип
created:        # Автоматично (плагін Update Time on Edit)
updated:        # Автоматично
---
```

### Location — особлива властивість

`Location` — єдина властивість, яка може стати **«тіньовою сутністю»** (shadow entity) у графі. Це означає: якщо адреса згадується в кількох нотатках, ви можете зробити з неї окрему нотатку і зв'язати через `[[]]`.

**Але:** Location — це NOT повноцінна сутність. Вона не матиме власного шаблону і не повинна з'являтися як вузол рівня Person чи Organization.

```
Person.md:
  Location: [[Kyiv, Podil district]]  ← тіньова сутність

Organization.md:
  Location: [[Kyiv, Podil district]]  ← той самий вузол

→ У графі: два вузли з'єднані через Kyiv, Podil district
```

### Date-Time — НЕ може бути тіньовою сутністю

Якщо дата потребує окремої нотатки → перетворіть її на `Event`.

## Теги і кольори графа

Теги виконують **тільки одну функцію** — фарбують граф. Жодного аналітичного значення самі по собі не несуть.

| Тег | Колір у графі (рекомендовано) |
|-----|-------------------------------|
| `#person` | синій |
| `#company` | помаранчевий |
| `#domain` | зелений |
| `#IP` | червоний |
| `#account` | фіолетовий |
| `#email` | жовтий |
| `#phone` | рожевий |
| `#TTP` | темно-червоний |
| `#weapon` | сірий |
| `#event` | бірюзовий |
| `#indicator` | білий |
| `#intel_prop` | золотий |

> **Правило:** Якщо у нотатки кілька тегів — в графі фарбується **тільки один**. Визначте заздалегідь, яким кольором відображається кожен тип.

## Стандарти іменування (naming conventions)

Послідовне іменування — це не бюрократія, це можливість використати **Replace All** для масового перейменування, коли ви імпортуєте сотні субдоменів або акаунтів.

| Тип | Формат | Приклад |
|-----|--------|---------|
| Account | `[username]_[Platform]` | `potus_Facebook` |
| Asset | `[Parent]_[Asset]` | `house_JohnAdams` |
| Crypto Wallet | `[Parent]_[CryptoWallet]-[num]` | `JohnAdams_BTC-1` |
| Domain | без протоколу і порту | `www[.]example[.]com` |
| Event | `[yyyy.mm.dd]-[location]-[event]` | `1979-Iran-IslamicRevolution` |
| Host IP | легітимна IPv4/IPv6 | `8[.]8[.]8[.]8` |
| Person (відомий) | повне ім'я | `Joe Biden` |
| Person (кілька однакових) | `[Name]-[IDno]` | `TimWolf-22` |
| Person (невідомий) | `Person-[alphanum]` | `Person-1` |
| Organization (невідома) | `Org-[alphanum]` | `Org-1` |

> **Важливо:** Квадратні дужки навколо крапок у IP і доменах — це стандарт **дефангування (defanging)**. Це робить посилання некліковним і захищає від випадкового переходу на шкідливий ресурс.

## Логіка побудови графа

Граф Obsidian відображає всі `[[подвійні посилання]]` між нотатками як ребра між вузлами. Таким чином:

1. Ви створюєте нотатку `JohnAdams` (Person)
2. Всередині пишете `Accounts: [[johnadams_Twitter]], [[jadams_LinkedIn]]`
3. Obsidian автоматично будує граф: JohnAdams → johnadams_Twitter, JohnAdams → jadams_LinkedIn

**Ключовий принцип:** Посилання у нотатці — це ребро графа. Чим більше правильних посилань, тим точніший граф.

### Що НЕ треба робити:

- Не посилайтесь на `Location` як на повноцінну сутність
- Не дублюйте одну й ту саму особу в кількох нотатках
- Не використовуйте посилання всередині `# Notes` (там вільний текст, не структура)
