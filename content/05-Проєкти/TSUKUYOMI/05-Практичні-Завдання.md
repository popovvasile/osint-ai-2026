## Завдання 1: Базовий WEBINT-цикл

**Рівень:** Початковий  
**Час:** 30-45 хв  
**Модулі:** `data_recognition_ingestion` → `web_search_osint`

### Завдання:

Проведіть WEBINT-дослідження відкритої компанії на вибір (публічна, реально існуюча). Наприклад: Ukrzaliznytsia, Naftogaz, Kyivstar — або будь-яка публічна компанія з вашої країни.

**Що зробити:**

```
1. Ініціалізуйте TSUKUYOMI
2. Активуйте data_recognition_ingestion з базовою інформацією про компанію
3. Активуйте web_search_osint з параметрами:
   - target_entity: [назва компанії]
   - intelligence_requirement: "корпоративна структура, ключові особи, публічні ризики"
   - temporal_constraints: останні 2 роки
4. Збережіть сесію
```

**Що здати:**
- Скриншот або текст відповіді з тегами `//RESULT` та `//ANOMALY`
- Коментар: які аномалії виявила система? Чи погоджуєтесь ви з оцінкою?

## Завдання 2: Стратегічний аналіз з кількома модулями

**Рівень:** Середній  
**Час:** 60-90 хв  
**Модулі:** `strategic_scenario_modeling` → `actor_capability_assessment` → `summarization_next_steps`

### Завдання:

Оберіть реальний поточний геополітичний кейс (регіональна напруга, торговий конфлікт, санкційний тиск). Мета — побудувати аналітичний продукт з трьох модулів як pipeline.

**Що зробити:**

```
Крок 1: strategic_scenario_modeling
- Введіть контекст кейсу (3-5 речень)
- time_horizon: short-term (3-6 місяців)
- Запишіть ймовірності трьох сценаріїв

Крок 2: actor_capability_assessment  
- Оцініть потенціал одного з ключових акторів кейсу
- Зверніть увагу на capability gaps

Крок 3: summarization_next_steps
- Запросіть executive summary
- Порівняйте: чи співпадає summary з вашим власним розумінням ситуації?
```

**Що здати:**
- Три блоки виводу (по одному з кожного модуля)
- Ваша оцінка: наскільки точно система відкалібрувала ймовірності? Де ви б не погодились і чому?

## Завдання 3: Побудуйте власний міні-модуль

**Рівень:** Просунутий  
**Час:** 2-3 год  
**Тема:** Prompt engineering + архітектура TSUKUYOMI

### Завдання:

Розробіть власний `.tsukuyomi`-модуль для конкретної OSINT-задачі. Наприклад:
- Аналіз Telegram-каналу на предмет координованої інформаційної кампанії
- Моніторинг судових реєстрів на предмет активу підозрюваного
- Аналіз LinkedIn-профілю для верифікації особи

**Мінімальна структура вашого модуля:**

```json
{
  "id": "your_module_id",
  "version": "1.0.0",
  "title": "Module XX: Ваша назва",
  "description": "Детальний опис",
  "type": "operational_module",
  "dependencies": ["data_recognition_ingestion"],
  "input_requirements": [
    {
      "name": "target",
      "type": "string",
      "description": "Об'єкт аналізу",
      "required": true
    }
  ],
  "output_schema": {
    "format": "structured",
    "standard_tags": ["//RESULT", "//QUERY", "//ANOMALY"],
    "fields": [...]
  },
  "execution_sequence": [
    {"step": 1, "operation": "...", "actions": [...]}
  ],
  "prompt": "Детальні інструкції для LLM щодо виконання аналізу..."
}
```

**Тест модуля:**

```
Збережіть файл як your_module.tsukuyomi
Завантажте в Claude Projects або додайте в папку modules/
Активуйте: Activate module: your_module_id
Перевірте, чи вивід відповідає вашій output_schema
```

**Що здати:**
- Файл `.tsukuyomi` (JSON)
- Скриншот тесту: вхідні дані + структурований вивід
- Рефлексія: що виявилось складним у написанні `"prompt"` всередині JSON? Як промпт впливає на якість аналізу?
