# ДЗ-05: OSINT-скрейпер
> [[02-Домашні-завдання/index|Усі завдання]] · [[01-Уроки/Урок-05-Соцмережі-та-медіапростір|Урок]]

**Урок:** Урок-05-Соцмережі-та-медіапростір

## Мета

Напишіть Python-проєкт, що збирає дані з однієї соцмережі з лекції (Telegram · Discord · WhatsApp) або схожої (Reddit, Mastodon, публічний Telegram-канал, YouTube-коментарі, RSS-медіа).

Мета — не «витягнути все», а зробити стійкий, інкрементний колектор, який поважає ліміти джерела й складає результат у єдину канонічну модель — так само, як проєкт-кейс із цієї лекції (Матеріали-Урок-05-Флот-скрейперів).

## Обовʼязкові вимоги

1. **Інкрементний збір** — тягніть нове за cursor / останнім id, а не все щоразу. Повторний запуск продовжує з того місця, де зупинився.
2. **Канонічна модель** — зберігайте у спільну таблицю/файл з полями `author` · `url` · `date` · `text` (+ медіа за потреби). Формат: SQLite або CSV / JSONL.
3. **Повага до лімітів** — пейсинг (затримка між запитами) + обробка rate-limit / 429 з backoff. Жодних банів.
4. **Стійкість і dedup** — один збій джерела не валить увесь прогін; логування; дедуплікація за унікальним ключем (напр. url або id), тож повторний запуск ідемпотентний.
5. **Конфіг і запуск** — секрети (ключі/токени) через `.env` поза кодом; README з інструкцією запуску; `requirements.txt`. Dockerfile — бонус.

## Бонуси

- Ротація кількох акаунтів / ключів (щоб жоден не «світився»).
- Проксі-вихід для збору.
- Дашборд зі статистикою збору.
- Backfill історії джерела (одноразовий добір старих записів).
- Docker / docker-compose.

## Підказки

- Візьміть джерело з офіційним або публічним доступом — менше тертя з анти-абʼюзом, легше вкластися в дедлайн.
- Почніть із канонічної таблиці та dedup-ключа — на ній тримається все інше.
- Ліміт роздивіться емпірично: залогуйте код відповіді й заголовки `Retry-After` / `X-RateLimit-*`, а не вгадуйте (як у кейсі з FloodWait).
- Один прогін = невелика партія; хай курсор рухається поступово.
