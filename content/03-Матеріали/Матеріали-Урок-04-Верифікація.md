## З Уроку 2 до Уроку 3: як GenAI допомагає *і* підриває верифікацію

У Урок-02-GenAI-для-аналітика ти вже бачив: LLM **не «знає» факти**, а **передбачає правдоподібний текст**; звідси галюцинації, упередження й залежність від контекстного вікна. **Урок 4** перевертає це в робочу дисципліну: *кожен вивід моделі — гіпотеза*, а істину встановлюють **джерела, метадані, інструменти та ланцюжок доказів**.

| Ідея з Уроку 2 | Як використовувати в верифікації (Урок 4) |
|----------------|---------------------------------------------|
| **Галюцинації та «впевнений тон»** | Не плутати красиву відповідь LLM із підтвердженим фактом; завжди мати **незалежну** перевірку (архів, EXIF, reverse search, офіційний реліз). |
| **Knowledge cutoff** | Для подій після дати тренування моделі — **RAG / пошук / первинні джерела** (див. блок RAG у Уроці 2), а не «пам’ять» моделі. |
| **Температура** | Для **витяжки фактів, JSON, чеклистів** тримай низьку температуру (**0.0–0.2**); трохи вище (**0.2–0.3**) лише там, де потрібна обережна інтерпретація (опис сцени), але **не** для юридичних висновків. |
| **Структурований вивід** | Промпти нижче вже розбиті на секції — додавай **явний формат** (маркери, таблиця, JSON), щоб потім **порівняти** з тим, що дають InVID, ExifTool, ACH у Arkham. |
| **RAG / grounding** | Якщо аналізуєш **великий корпус** (звіти, експорти), спершу **завантаж у довірений RAG** (NotebookLM, власна база з Уроку 2) або в **Arkham ingest**, а LLM питай **лише по цитованому контексту**. |
| **Confirmation bias моделі** | Не підгодовувати модель формулюванням «доведи що це фейк» без альтернативи; для гіпотез краще **ACH-рамка** (кілька пояснень одних даних) — узгоджується з практикою Уроку 3. |

**Практичне правило курсу:** спочатку **інструментальна** або **архівна** верифікація (InVID, Wayback, EXIF, TinEye…), потім LLM як **асистент узагальнення** — не навпаки.

## Промпти для верифікації через LLM

Нижче — **готові шаблони**, які навмисно узгоджені з підходом Урок-02-GenAI-для-аналітика: роль, структура секцій, явний формат висновку, мінімізація «вільної прози». Після відповіді моделі **обов’язково** пройди хоча б короткий чеклист: (1) чи є **посилання на пікселі / написи / тіні**, які можна звірити з EXIF або картами; (2) чи не **вигадані** назви місць чи дат; (3) що з розділу «Рекомендовані кроки» ти реально виконав інструментами з першої частини цього файлу.

**Рекомендовані параметри (нагадування з Уроку 2):** для цих промптів логічна температура **0.1–0.25**; якщо модель підтримує **JSON mode / structured output** — увімкни для табличних висновків.

### Промпт 1 — Forensic аналіз зображення

```
Ти — forensic-аналітик медіаконтенту.
Проаналізуй це зображення детально.

СЕКЦІЯ 1 — ОПИС:
Перерахуй всі видимі об'єкти, написи, орієнтири, людей, транспорт.

СЕКЦІЯ 2 — ОСВІТЛЕННЯ:
- Де знаходиться джерело світла?
- Чи відповідають тіні джерелу?
- Чи рівномірне освітлення на всіх об'єктах?

СЕКЦІЯ 3 — ОЗНАКИ МАНІПУЛЯЦІЇ:
Перевір і вкажи наявність або відсутність:
- Розмиття або артефакти на межах об'єктів
- Аномалії у волоссі, вухах, руках, пальцях
- Нечитабельний або безглуздий текст
- Нерівномірна глибина різкості
- Повторювані патерни у фоні

СЕКЦІЯ 4 — ГЕОЛОКАЦІЯ:
- Регіон світу (за мовою написів, архітектурою, рослинністю)
- Конкретна локація якщо можливо визначити

СЕКЦІЯ 5 — ХРОНОЛОГІЯ:
- Чи відповідає сезон, одяг, техніка заявленому часу?
- Будь-які хронологічні невідповідності?

ВИСНОВОК:
- Оцінка автентичності: Натуральне / Підозріле / Очевидно згенеровано / AI-generated
- Ключові ознаки що вплинули на оцінку (конкретно)
- Рекомендовані додаткові кроки верифікації
```

## MindsDB + ArkhamMirror (практичний модуль)

> **Покроковий гайд для студентів** (Docker на Linux/macOS, запуск обох сервісів, мережа `shattered-network`, `CREATE DATABASE`): Гайд-Docker-MindsDB-та-ArkhamMirror

### Для чого ця зв'язка

ArkhamMirror відповідає за ingestion/verification workflow (documents, claims, contradictions, ACH), а MindsDB дає SQL-шар поверх даних Arkham PostgreSQL для швидкої аналітики та AI-driven запитів.

**Що це дає на практиці:**
- миттєві зрізи по `ingest jobs`, `projects`, `documents`;
- менше ручних скриптів для метрик курсових кейсів;
- єдину точку доступу для подальшої автоматизації.

### Локальна схема контейнерів

- `shattered-postgres` (Arkham DB) у мережі `shattered-network`
- `mindsdb` (MindsDB Studio) зазвичай у `bridge`

Щоб MindsDB бачила Arkham DB, додай її в мережу Arkham:

```bash
# Перевірити поточні мережі
docker ps --format "table {{.Names}}\t{{.Networks}}"

# Підключити mindsdb до мережі Arkham
docker network connect shattered-network mindsdb

# Тест DNS + TCP до Arkham PostgreSQL
docker exec mindsdb python -c "import socket; print(socket.gethostbyname('shattered-postgres')); s=socket.create_connection(('shattered-postgres',5432),timeout=5); print('ok'); s.close()"
```

### Підключення Arkham DB у MindsDB

**MindsDB UI:** `http://localhost:47334`  
В SQL Editor виконай:

```sql
CREATE DATABASE arkham_pg
WITH ENGINE = 'postgres',
PARAMETERS = {
  "host": "shattered-postgres",
  "port": 5432,
  "user": "arkham",
  "password": "arkhampass",
  "database": "arkhamdb"
};

SHOW DATABASES;
```

### Робочі запити для Уроку 3

```sql
-- 1) Стан ingestion pipeline
SELECT status, COUNT(*) AS jobs
FROM arkham_pg.arkham_ingest.jobs
GROUP BY status
ORDER BY jobs DESC;

-- 2) Останні оброблені файли
SELECT id, filename, status, created_at
FROM arkham_pg.arkham_ingest.jobs
ORDER BY created_at DESC
LIMIT 10;

-- 3) Розподіл документів по проєктах
SELECT
  p.name AS project_name,
  COUNT(d.id) AS docs,
  COALESCE(SUM(d.file_size), 0) AS total_bytes
FROM arkham_pg.arkham_frame.projects p
LEFT JOIN arkham_pg.arkham_frame.documents d ON d.project_id = p.id
GROUP BY p.name
ORDER BY docs DESC;
```

### Як інтегрувати у workflow верифікації

1. **ArkhamMirror:** ingest + перевірка (Media Forensics / Claims / ACH).  
2. **MindsDB:** SQL-контроль метрик якості (`completed/failed`, обсяг кейсу, прогрес).  
3. **Звіт:** включити результати у `Reports/Export` як доказ відтворюваності процесу.

### Зв’язок з Уроком 2 (агенти, MCP, «розмова з даними»)

У Урок-02-GenAI-для-аналітика обговорювались **якість промпта** та **обмеження моделі**. У **MindsDB** ти можеш поєднати обидва світи: **табличні метрики** (SQL по `arkham_*`) + **AI Agent** для запитань природною мовою — але відповідь агента залишається **гіпотезою**, поки її не звірив з **документами в Arkham** або з **первинним джерелом**. Офіційно про **MCP** (підключення зовнішніх агентів до MindsDB): [Model Context Protocol — MindsDB](https://docs.mindsdb.com/model-context-protocol/overview).
