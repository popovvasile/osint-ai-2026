### Слайд 2 — Навіщо моніторинг у реальному часі?

**Реактивний OSINT** — ви шукаєте коли вже пізно
**Проактивний моніторинг** — ви знаєте раніше за всіх

Сценарії:
- Нова згадка клієнта/партнера у пресі → реакція до публікації
- Поява витоку даних → реагування в години, не дні
- Зміна наративу навколо об'єкту → рання ескалація
- Нова активність відстежуваної особи → оновлення досьє

### Слайд 4 — RSS: основа безкоштовного моніторингу

**RSS (Really Simple Syndication)** — стандартний протокол підписки на оновлення

**Що доступно через RSS (2025-2026):**
- Новинні сайти (99% мають RSS)
- YouTube-канали: `https://www.youtube.com/feeds/videos.xml?channel_id=ID`
- Reddit: `https://reddit.com/r/ukraine.rss`
- Google News: `https://news.google.com/rss/search?q=запит`
- GitHub: releases, commits, issues

**Рекомендовані RSS-читачі:** Inoreader (250 безкоштовних фідів), Feedly

### Слайд 6 — Google Alerts і News

```
Запит: "Іван Петренко" OR "Ivan Petrenko"

Джерела: новини + блоги + веб
```

### Слайд 7 — Keyword Alerting: архітектура

```
Джерела → Збір → Фільтрація → Нормалізація → Алерт
   │          │         │            │            │
RSS, API   Cron/      Keyword    Дедуплік.   Email/
Telegram  Scheduler   match      та оцінка  Telegram/
Web       (Python)               достовірн. Slack
```

**Базова Python реалізація:**
```python
import schedule, time

def check_and_alert():
    results = rss_reader.fetch_all()
    matches = keyword_filter(results, keywords=["TechUA", "Петренко"])
    for match in deduplicate(matches):
        send_telegram_alert(match)

schedule.every(30).minutes.do(check_and_alert)
while True:
    schedule.run_pending()
    time.sleep(60)
```

### Слайд 10 — Управління алертами: уникнення перевантаження

**Проблема:** занадто багато алертів = аналітик ігнорує всі

**Рішення — рівні пріоритетів:**
```
🔴 КРИТИЧНИЙ  → миттєво (Telegram/SMS)
   Нова стаття в ЗМІ, витік даних, кримінальна згадка

🟡 ВАЖЛИВИЙ   → щоденний дайджест (email)
   Нові соцмережеві пости, зміна ролі, нова компанія

🟢 ФОНОВИЙ    → тижневий огляд (RSS)
   Загальні тематичні новини, слабко пов'язані згадки
```

### Слайд 11 — Моніторинг темної мережі (базово)

**Без "екзотики":**
- **HaveIBeenPwned** — перевірка email на витоки (API безкоштовний)
- **BreachDirectory** — пошук по компрометованим базам
- **DeHashed** — платний але широкий пошук
- **Leak-Lookup** — агрегатор витоків

```python
import requests

def check_haveibeenpwned(email):
    headers = {"hibp-api-key": "ваш_ключ"}
    r = requests.get(
        f"https://haveibeenpwned.com/api/v3/breachedaccount/{email}",
        headers=headers
    )
    return r.json() if r.status_code == 200 else []
```

### Слайд 12 — Дашборд моніторингу: практична архітектура

```
Рівень збору:

Рівень виводу:
  🔴 Критично → Telegram-бот алерт
  🟡 Важливо → щоденний email дайджест
  🟢 Фоново → тижневий Obsidian-звіт
```

## Нотатки доповідача

### До слайду 3 — Піраміда інструментів
Акцент: 80% потреб покривається безкоштовними інструментами якщо правильно налаштувати. Дорогі платформи (Recorded Future, Crimewall) дають перевагу в масштабі і в доступі до закритих джерел — але для більшості задач аналітика вони не потрібні.

### До слайду 5 — Telegram RSS
Telegram — найважливіший канал для пострадянського простору. Демонстрація: перетворіть публічний Telegram-канал у RSS прямо під час лекції через rss.app. Це займає 2 хвилини і студенти бачать результат.

### До слайду 10 — Управління алертами
"Аналітик що отримує 500 алертів/день не читає жодного" — підкресліть. Правильне налаштування пріоритетів = різниця між корисним інструментом і шумом.
