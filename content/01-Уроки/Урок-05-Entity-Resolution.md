### Слайд 2 — Проблема: один і той самий, але різний

**Реальна ситуація розслідування:**

Ви зібрали дані з 8 джерел. Маєте:
- `«Іван Петренко, CEO TechUA»` — LinkedIn
- `«I. Petrenko, head of TechUA Ltd»` — реєстр компаній
- `«ivanp_kyiv»` — GitHub
- `«ivan.petrenko90@gmail.com»` — витік бази даних
- `«@ivan_tech_ua»` — Telegram
- `«+38050-xxx-xxxx»` — WhatsApp
- `«Іван П., директор»` — судовий реєстр
- `«IvanUA»` — форум криптовалют

**Питання:** це одна людина чи 8 різних записів?

**Entity Resolution (Розпізнавання сутностей)** — процес визначення того, що різні записи з різних джерел стосуються одного реального об'єкта.

### Слайд 3 — Що таке «сутність» в OSINT

**Сутність (Entity)** = будь-який реальний об'єкт, що можна ідентифікувати та описати атрибутами.

| Тип сутності | Приклади | Ключові атрибути |
|---|---|---|
| **Особа (Person)** | Людина, псевдонім | Ім'я, дата народження, фото, нікнейм |
| **Організація (Organization)** | Компанія, ГО, держорган | Назва, ідентифікаційний код, юрисдикція |
| **Локація (Location)** | Адреса, координати | GPS, країна, індекс |
| **Артефакт (Artifact)** | Email, IP, домен, телефон | Значення, протокол, реєстратор |
| **Подія (Event)** | Зустріч, транзакція | Дата, учасники, місце |
| **Крипто-актив** | Гаманець, NFT | Адреса, мережа, баланс |

**Граф = Сутності (вузли) + Зв'язки (ребра) + Атрибути + Вага**

### Слайд 4 — Три методи Entity Resolution

#### 1. Детерміністичний (точний збіг)
- Однаковий email → одна особа (впевненість: **10/10**)
- Однаковий телефон → одна особа (впевненість: **9/10**)
- Однаковий хеш фото → одне зображення (впевненість: **10/10**)

#### 2. Ймовірнісний (нечіткий збіг)
- «Іван Петренко» + «I. Petrenko» + спільна компанія → ймовірно та сама людина (впевненість: **7/10**)
- Транслітераційні варіанти + збігаюча посада → **6/10**

#### 3. AI-підхід (семантичний збіг, 2025–2026)
- Векторні ембедінги (embeddings) порівнюють семантичну схожість записів
- Великі мовні моделі (ВММ / LLM) розбирають контекстуальні підказки
- Graph Neural Networks прогнозують приховані зв'язки

> **Статистика 2025:** KnowCTI досягає **92.96% точності** на витяжку сутностей (entity extraction) з CTI-текстів.

### Слайд 5 — Ідентифікаційні якорі

**Надійні якорі (deterministic identifiers):**

| Якір | Унікальність | Постійність | Примітка |
|---|---|---|---|
| Email | Висока | Висока | Ключ до більшості сервісів |
| Телефон | Висока | Середня | Змінюється рідше, ніж здається |
| Нікнейм | Середня | Висока | Люди дуже послідовні |
| Фото профілю | Висока | Середня | Зворотний пошук зображень |
| Крипто-гаманець | Дуже висока | Висока | Незмінна публічна адреса |

**Слабкі якорі (потребують підтвердження):**
- Ім'я та прізвище — збігається у тисячах осіб
- Посада — змінюється, не унікальна
- Локація — може бути VPN або навмисно помилковою

**Правило 2+:** для однозначної ідентифікації потрібно **мінімум 2 незалежні надійні якорі**.

### Слайд 6 — Каскад ідентифікаторів

**Принцип:** один ідентифікатор → кілька нових → ще більше зв'язків.

```
Email  ──→  BreachData  ──→  інші акаунти з тим самим email
  │                                    │
  └──→  Gravatar  ──→  фото  ──→  Google Lens  ──→  соцмережі
  
Нікнейм  ──→  Sherlock / Maigret  ──→  список 500+ платформ
              │
              └──→  GitHub  ──→  реальне ім'я + локація + репозиторії
              └──→  Reddit  ──→  пости + зацікавлення
              └──→  Steam  ──→  ігровий профіль + країна

Телефон  ──→  WhatsApp  ──→  ім'я + фото + «бачили нещодавно»
           └──→  Telegram  ──→  username + публічні групи
```

**Мета:** перетворити один відомий факт на повний профіль.

### Слайд 7 — Collision Detection: Уникайте помилок атрибуції

**Найнебезпечніша помилка OSINT:** приписати факти однієї людини її однофамільцеві.

**Перевірка при збігу імен — обов'язковий чеклист:**

- [ ] Збігається компанія / сфера діяльності?
- [ ] Збігається географічна локація?
- [ ] Збігається орієнтовний вік / фото?
- [ ] Є хоча б 2 незалежні факти, що прив'язують до конкретної особи?
- [ ] Чи перевірено альтернативну гіпотезу (це ІНША людина)?

**Якщо сумніваєтесь → розбийте на дві окремі сутності:**
- `ent_ivan_petrenko_techUA` (CEO компанії)
- `ent_ivan_petrenko_kherson` (судовий реєстр Херсон)

Краще мати дві окремі сутності, які потім виявляться однією, ніж одну злиту, яка насправді дві.

### Слайд 8 — Від даних до графа: пайплайн (pipeline)

```
Збір даних          Entity Extraction       Нормалізація
(сирі джерела)  →   (NER, regex, LLM)   →  (стандартизація)
     │                                           │
     └── веб-сторінки                            └── «Іван» = «Ivan»
     └── PDF-документи                           └── «+380» = «38»
     └── соцмережі                               └── дата ISO 8601
     └── бази даних
         
Нормалізація    →   Deduplication     →    Linking         →    Граф
                    (злиття дублікатів)     (встановлення        (Neo4j /
                    Fuzzy match /           зв'язків)            Cytoscape)
                    Vector similarity
```

**Ключові компоненти:**
1. **NER (Named Entity Recognition)** — автоматичне виявлення сутностей у тексті
2. **Нормалізація** — єдиний формат для порівняння
3. **Дедублікація** — злиття дублікатів
4. **Linking** — встановлення зв'язків між сутностями
5. **Граф** — фінальна структура для аналізу та візуалізації

### Слайд 13 — Flowsint: Збагачувачі домену (Domain Enrichers)

**Починаємо розслідування з домену — наприклад `techUA.com`:**

| Збагачувач | Що робить | Результат |
|---|---|---|
| **DNS Resolution** | Резолвить домен в IP | `techUA.com → 185.x.x.x` |
| **Reverse DNS** | Знаходить домени на IP | `185.x.x.x → 12 доменів` |
| **Subdomain Discovery** | Перебирає піддомени | `mail.techUA.com, api.techUA.com` |
| **WHOIS Lookup** | Реєстраційна інформація | Дата, реєстратор, контакт |
| **Domain History** | Хто раніше володів | Минулі реєстрації |
| **Domain → ASN** | Знаходить AS-провайдера | `AS12345 (Kyivstar)` |
| **Domain → Website** | Перетворює на web-сутність | Для подальшого збагачення |

**Практика:** з одного домену за 2-3 хвилини — повна карта технічної інфраструктури.

### Слайд 14 — Flowsint: Збагачувачі IP та мережі

**IP → ASN → CIDR → список IP-адрес:**

```
Крок 1: IP Information
  → Геолокація (країна, місто, координати)
  → Провайдер (ISP)
  → Тип (хостинг, residential, Tor exit node)
  → Reputation (чи є в blocklist)

Крок 2: IP → ASN
  → Автономна система (ASN)
  → Власник AS (хто реально контролює)
  → Країна реєстрації

Крок 3: ASN → CIDRs
  → Всі IP-діапазони що належать AS
  → Масштаб: може бути тисячі IP

Крок 4: Organization → ASN
  → Якщо відома компанія → знайти всі її AS
```

**Навіщо це потрібно в OSINT:**
- Кластеризація сервісів одного актора за інфраструктурою
- Виявлення спільного хостингу для різних доменів
- Attribution (атрибуція) кібератак за мережевими артефактами

### Слайд 15 — Flowsint: Email та особа

**Email — найпотужніший відправний якір:**

| Збагачувач | Що повертає |
|---|---|
| **Email → Breaches** | Список витоків (HaveIBeenPwned / Dehashed) |
| **Email → Domains** | Домени асоційовані з цим email |
| **Email → Gravatar** | Фото профілю, ім'я, опис |
| **Individual → Organization** | Організаційна приналежність |
| **Individual → Domains** | Домени зареєстровані на особу |

**Типовий ланцюг:**
```
email@domain.com
  ├─ [Breaches] → 3 витоки → паролі, телефон, ім'я
  ├─ [Gravatar] → фото + username
  ├─ [→ Domains] → techUA.com, ivan-petrenko.ua
  └─ [→ Individual] → "Іван Петренко, CEO"
       └─ [Individual → Org] → TechUA Ltd
```

**Один email може розкрити повний профіль особи за 5–10 хвилин.**

### Слайд 18 — Flowsint: Веб-сайт та телефон

### Слайд 20 — Flowsint: Практичний workflow

**Кейс: розслідування підозрілого домену**

```
Крок 1: Додати сутність
  + New Entity → Domain → "suspicious-invest.ua"

Крок 2: Запустити збагачувачі
  → DNS Resolution     : 194.x.x.x (Hetzner, Німеччина)
  → WHOIS             : зареєстровано 14 днів тому, Privacy Guard
  → Subdomain Discovery: login.suspicious-invest.ua, admin.suspicious-invest.ua
  → Domain History    : до 2 місяців тому — парковий домен

Крок 3: Слідуємо за IP
  → IP Information    : shared hosting, 47 доменів на тому ж IP
  → Reverse DNS       : 3 схожих "invest" домени на тому ж IP
```

### Слайд 28 — OpenPlanter: Рекурсивні суб-агенти

**Ключова особливість OpenPlanter:** агент може породжувати суб-агентів для паралельної роботи.

```
Головний агент: "Дослідити мережу контрагентів ТОВ TechUA"
  │
  ├─ [subtask] Суб-агент 1: "Перевірити всіх директорів TechUA"
  │     └─ Знаходить: 3 директори → перевіряє кожного в реєстрах
  │
  ├─ [subtask] Суб-агент 2: "Знайти пов'язані компанії за адресою"
  │     └─ Знаходить: 8 компаній на тій самій адресі
  │
  ├─ [subtask] Суб-агент 3: "Перевірити державні контракти 2023-2025"
  │     └─ Знаходить: 12 контрактів на 47 млн грн
  │
  └─ [execute] Агент-синтезатор: об'єднує всі результати
         └─ Генерує звіт: зв'язки, ризики, рекомендації
```

**Параметри рекурсії:**
```bash
--recursive          # увімкнути рекурсію (за замовчуванням)
--max-depth 4        # максимальна глибина рекурсії
--max-steps 100      # максимум кроків на виклик
--acceptance-criteria # перевірка результатів суб-агентів
```

### Слайд 34 — Collision Detection в інструментах

**Як уникнути помилок при роботі з Flowsint та OpenPlanter:**

**У Flowsint:**
- Якщо підозрюєте collision — **не зливайте** вузли вручну без перевірки
- Додайте ребро `POSSIBLY_SAME_AS` замість злиття
- Приберіть атрибут `verified: false` — він видно у графі

**У OpenPlanter:**
```bash
# Агент сам попереджає про можливі collision:
"Знайдено 2 сутності з ім'ям 'Олексій Шевченко':
  - ent_shev_kyiv: CEO TechUA, Київ, 1985
  - ent_shev_kharkiv: директор MetalUA, Харків, 1971
  Рекомендація: НЕ зливати — різні особи. Впевненість: 8/10"
```

**Правило практики:** при будь-якому сумніві — окремі вузли. Аналітик може злити пізніше, але не може "розлити" злиту сутність без втрати контексту.

### Слайд 36 — Підсумок уроку

   - 30+ збагачувачів, Neo4j, Docker, N8n-інтеграція

5. **OpenPlanter** — AI-агент для корпоративних розслідувань
   - 19 інструментів, рекурсивні суб-агенти, Cytoscape.js граф

6. **Інтеграція:** Flowsint (технічна розвідка) → OpenPlanter (корпоративна розвідка)

7. **Якість:** кожен зв'язок потребує оцінки впевненості 1–10 та джерела

**Наступний урок:** Теорія графів та графи знань — застосування в AI та OSINT.

## Нотатки доповідача

### До слайду 2 — Проблема
Починайте з конкретного прикладу. Намалюйте на дошці або покажіть у слайді: 8 записів про одну людину з різних джерел. Запитайте аудиторію: "Скільки тут різних людей?" Зачекайте відповіді. Це найкращий вступ до поняття entity resolution — всі одразу розуміють практичну проблему.

### До слайду 4 — Три методи
Наголосіть на різниці між детерміністичним і ймовірнісним. Приклад: якщо знайдені два записи з однаковим email — це той самий (детерміністично, 10/10). Але якщо ім'я + компанія + місто збігаються — це ймовірно та сама людина, але потрібна перевірка. Статистика KnowCTI (92.96%) — гарний аргумент для AI-підходу.

### До слайду 6 — Каскад ідентифікаторів
Намалюйте каскад на дошці в реальному часі. Почніть з email → покажіть кілька кроків. Студенти мають зрозуміти, що один ідентифікатор — це лише початок. Ключова думка: OSINT — це не пошук одного факту, а побудова мережі пов'язаних фактів.

### До слайду 7 — Collision Detection
Розкажіть реальну помилку з практики (можна анонімізовану): аналітик приписав пост у соцмережах публічній особі, але це був її однофамілець. Наслідки: неправильний висновок у звіті. Це підкреслює важливість перевірки collision.

### До слайду 11 — Встановлення Flowsint
Демонстрація LIVE: якщо є підготовлений сервер з Flowsint — покажіть реєстрацію та перший запуск. Якщо ні — покажіть скріншоти з GitHub README. Зверніть увагу: 3 команди і все готово. Docker вирішує всі питання залежностей.

### До слайду 13–18 — Збагачувачі Flowsint
Демонстрація LIVE обов'язкова. Запустіть реальний збагачувач на публічному домені (наприклад, домен НГО або медіа). Студенти мають побачити, як граф будується в реальному часі. Найефективніший момент уроку — коли на екрані з'являються нові вузли і ребра автоматично.

### До слайду 16 — Maigret
LIVE демонстрація Maigret (або аналог Sherlock): оберіть нікнейм з аудиторії з дозволу студента. Запустіть Maigret/Sherlock. Результат — 20-40 платформ. Це завжди викликає реакцію аудиторії і добре закріплює тему ідентифікаційних якорів.

### До слайду 22 — Встановлення OpenPlanter
Якщо є час — покажіть завантаження .AppImage на Linux або покажіть CLI. Найпростіший варіант для класу: `pip install -e .` + `openplanter-agent --configure-keys`. Зверніть увагу: OpenPlanter потребує API-ключів для хмарних моделей, але Ollama безкоштовний.

### До слайду 28 — Рекурсивні суб-агенти
Це ключова концепція OpenPlanter. Поясніть аналогію: один детектив і команда детективів. Рекурсивний агент = керівник, що розподіляє завдання. Покажіть `--max-depth 4` і поясніть: агент на глибині 4 вже не може породжувати нових агентів. Це захист від нескінченних петель.

### До слайду 30 — Практичний кейс
Якщо можливо — запустіть OpenPlanter з реальним датасетом ProZorro (відкриті дані). Навіть демо з 100-200 контрактами демонструє принцип роботи. Зверніть увагу на час: 18 хвилин — це швидше, ніж будь-який ручний процес.

### До слайду 31 — Порівняння
Наголосіть: ці інструменти **доповнюють**, а не замінюють один одного. Flowsint чудовий для технічного OSINT (домени, IP, email). OpenPlanter — для реєстрів і корпоративних зв'язків. Разом вони покривають весь спектр.

### До слайду 33 — Якість та впевненість
Нагадайте шкалу 1–10 з Уроку 2. Підкресліть: навіть якщо Flowsint або OpenPlanter автоматично знайшли зв'язок — ви зобов'язані перевірити його самостійно. AI — це помічник, не вирок. Впевненість нижче 7 — у звіт не включати або позначати окремо.

## Домашнє завдання

### Завдання 1 — Flowsint: Граф за доменом (обов'язкове)

Встановіть Flowsint (`git clone` + `make prod`). Виберіть публічний домен будь-якої відомої NGO або медіа (наприклад, dom.rferl.org, bellingcat.com або іншого публічного медіа).

1. Додайте домен як сутність у Flowsint
2. Запустіть усі доступні збагачувачі для домену
3. Слідуйте мінімум за 2 знайденими сутностями (наприклад, IP → ASN або email → gravatar)
4. Зробіть скріншот отриманого графу
5. Опишіть: що нового ви дізналися про об'єкт розслідування? Чи є несподівані зв'язки?

**Здача:** скріншот графу + текстовий аналіз (250–400 слів) + оцінка впевненості для кожного зв'язку (1–10).

1. Встановіть OpenPlanter CLI (`pip install -e .`)

3. Запустіть агента з завданням: "Знайди дублікати та пов'язані компанії в цьому датасеті"
4. Проаналізуйте виявлені зв'язки у Cytoscape-графі

**Здача:** знімок екрану графу + текстовий опис знахідок + список виявлених дублікатів або зв'язків (мінімум 3).

### Завдання 3 — Інтеграція: Flowsint → OpenPlanter (бажане)

Виконайте двохфазний пайплайн:

**Фаза 2 (OpenPlanter):** Використайте знайдені компанії як вхідні дані. Попросіть агента знайти їх у публічних реєстрах та перевірити, чи є зв'язки між ними.

**Здача:** опис кожної фази + підсумковий граф (або опис зв'язків) + висновок: чи знайдені нові зв'язки, яких не було б без двохфазного підходу?
